# TOPUYI 独立云部署（方案 C）

有米与 TOPUYI **不同主体**，无法环境共享。两小程序**各用各的云**，群、用户数据**不互通**，有米侧**无需改动**。

| 项目 | AppID | 云环境 |
|------|-------|--------|
| 有米 | `wx36a792be88fa919a` | `cloud1-3g4lff0x2b1fbba7`（保持不动） |
| TOPUYI | `wx3610c3ef05d1131e` | **新建独立环境**（见步骤 1） |

---

## 步骤 1：创建 TOPUYI 云环境（约 3 分钟）

1. 用 **TOPUYI** 项目 `mini_topuyi` 打开微信开发者工具  
2. 点击 **云开发** → **创建环境**（按提示开通，选按量计费即可）  
3. 创建完成后：**设置 → 环境设置** → 复制 **环境 ID**（形如 `cloud1-xxxxxxxx`）  
4. 打开 [`utils/cloud-config.js`](../utils/cloud-config.js)，把 `CLOUD_ENV_ID` 改成你的环境 ID：

```javascript
const CLOUD_ENV_ID = 'cloud1-你的新环境ID';
```

保存后重新编译小程序。

---

## 步骤 2：创建数据库集合（约 5 分钟）

在 **TOPUYI 云开发控制台 → 数据库**，新建集合：

| 集合名 | 权限建议 |
|--------|----------|
| `groups` | 仅管理端可读写，或按云函数访问需求配置 |
| `group_members` | 同上 |
| `users` | 若走云函数登录：仅管理端可读写；若客户端直写 users：仅创建者可读写 |

> 群控读写主要通过云函数，集合权限可与有米环境配置保持一致。

---

## 步骤 3：部署云函数（约 5 分钟）

在 TOPUYI 开发者工具，`cloudfunctions` 目录右键部署：

| 云函数 | 是否必须 | 说明 |
|--------|----------|------|
| `group-service` | **必须** | 房间/群控 |
| `user-service` | **必须** | 手机号登录 |
| `migrate-app-scope` | 不需要 | 仅共用云时给有米存量补标 |
| `cloudbase_auth` | 不需要 | 仅环境共享时需要 |

对每个必选项：**上传并部署：云端安装依赖**。

---

## 步骤 4：冒烟测试（约 10 分钟）

在 TOPUYI 开发者工具预览：

- [ ] 登录页：手机号登录成功  
- [ ] 房间页：列表加载无报错  
- [ ] 创建群成功  
- [ ] 另一账号/模拟器加入群  
- [ ] 管理员控灯，成员状态同步  
- [ ] 解散/退出群正常  

**不需要**测试有米；有米继续用原环境，互不影响。

---

## 步骤 5：TOPUYI 提审上线

冒烟通过后正常上传代码、提交审核。

---

## 有米需要做什么？

**什么都不用做。** 不要：

- 对有米环境部署本仓库的云函数  
- 执行 `migrate-app-scope` backfill  
- 配置环境共享  

---

## 常见问题

| 现象 | 处理 |
|------|------|
| 提示「请填写 TOPUYI 独立云环境 ID」 | 完成步骤 1，改 `cloud-config.js` |
| `Environment not found` | 环境 ID 填错，或未用 TOPUYI 账号创建环境 |
| `FunctionName` 找不到 | 未部署 `group-service` / `user-service` |
| 集合不存在 | 完成步骤 2 建表 |
